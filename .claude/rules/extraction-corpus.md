# Extraction corpus

- Never commit a real client document, scrubbed or not. Reproduce its arrangement as a generator entry in `fixtures_test.go`.
- Transcribe the arrangement only: which labels appear, where, and at what token granularity.
- Replace every TIN, party name, address, invoice number, account number, phone number and email address.
- Replace names that appear only in a footer, a logo caption or a bank block.
- Use `Adeyemi Trading Limited` and `Honeywell Group` as party names. Neither is a live customer.
- Emit no PDF `/Info` dictionary, file `/ID` or XMP packet from a generator.
- Record the scrubber and the date in the generator comment. A second person confirms the reproduction identifies nobody.
- Draw corpus TINs from `99999999-0101` upward. Never use `99999999-0001` to `99999999-0009`. The mock adapter triggers on `-0001` to `-0007`. It reserves `-0008` and `-0009` unallocated.
- Keep `TestCorpus_UsesOnlyFreeReservedTINs` green. It reads every `corpusLayouts` file.
- Keep `corpus_` files flat in `testdata/`. `TestFixtures_MatchTheirGenerator` counts top-level `.pdf` entries only.
- Regenerate with `go test ./internal/extraction/ -run TestFixtures -update`.
- Put `-update` after the package path. Before it, `go test` regenerates nothing and exits 0.
- Read the byte diff before you commit. Commit regenerated bytes with the generator change.
- Never hand-edit a PDF. `TestFixtures_MatchTheirGenerator` compares committed bytes with a fresh build.
- Register the `-update` flag once, as `fxUpdate`. A second registration panics the test binary.
- Read no clock, no random source and no map iteration order in the generator.
- One `fxLine` is one pdfium token in the `corpus_` layouts. A label and value on one `fxLine` arrive as one token.
- Chrome fixtures emit one `Tj` per glyph. The `fxLine` token lever does not apply to them.
- A new layout takes a builder and an `fxCorpus` entry in `fixtures_test.go`. Name the file `corpus_<name>.pdf`.
- Add a `corpusExpect` row in `corpus_test.go`. List only the fields the layout prints.
- Make every `corpusExpect` value readable from the new fixture. `TestCorpus_EveryExpectedValueAppearsInItsFixture` checks it.
- Add the file name to `corpusLayouts` and move its expected count. The set is hard-coded so a missing layout shows.
- Add the token count to `corpusTokenFloor` in `corpus_adversarial_test.go`. A layout without an entry fails.
- Add the `.pdf` to `requiredPDFs` and the `.docling.json` to `requiredGoldens` in `endtoend/harness_db_test.go`.
- Add an `expectByLayout` row in `endtoend/score_test.go`, with one key per written field.
- Give an empty list and an `eeAbsentCells` reason where the layout prints a field nowhere.
- Move `eeLayoutCount`, `eeWrittenCells`, `eeCorpusHits` and `eeCutReach` when a layout joins the scored set.
- Add an `eeLinesExpected` row in `endtoend/lines_test.go`. Take the count off the layout's golden.
- Add a `wildPairs` row in `endtoend/goldens_test.go` for each new `wild_*` arrangement. Name its as-printed sibling or an exemption with a reason.
- Make every `corpusExpect` value reachable by `Tier1Rules`. Otherwise list the pair in `t1aGaps` with a reason.
- A `t1aGaps` entry excuses a pair from the per-pair test only. The rate stays red until the rules reach it.
- Name a fixture that is not a layout outside the `corpus_` prefix. Add it to no layout registry.
- Keep `learned_*`, `rich_invoice`, `advisory_*`, `chrome_register*` and `dense_invoice` out of `corpusExpect`, `corpusLayouts` and `corpusTokenFloor`.
- A `wild_*` arrangement joins `expectByLayout` but no `corpus_` registry.
- Registering an `advisory_register*` fixture in `expectByLayout` removes `withholding_tax` from `wildUnprintedPhraseIDs` in the same commit.
- Read `wild_scanned_no_number.pdf` from its docling golden. pdfium reads zero tokens off it.
- Treat a zero token count in a layout walk as fatal. An empty read against an empty expectation proves nothing.
- Regenerate a docling golden by the procedure in `docling-sidecar.md`. `go test -update` never touches it.
- Reproduce a failing client invoice as a new layout with a failing `corpusExpect` row before the fix.
- A fix that is right for one tenant's producer is a learned rule, not a Tier-1 rule.
- Set `tier1RecallHits` and `tier1RecallPairs` to the measured values. Re-measure with `go test -count=1 -v -run TestTier1Accuracy ./internal/extraction/`.
- Set `tier1DecisionHits` and `tier1DecisionPairs` to the measured values. They are a measurement, not a ratchet.
- Set `eeCorpusHits` to the measured value. Re-measure with `go test -p 1 -count=1 -v -run TestRLS_EndToEnd ./internal/extraction/endtoend/`.
- Move `eeCorpusCells` only when a layout or a written field joins.
- Move each cell that changed between `eeRealMisses` and the hits, with a written reason per cell.
- The recall floor and `eeCorpusHits` only go up. Set each to what you measured, never to a target.
- Do not widen a distance dial past `TestTier1_DialsStayInsideTheirMeasuredWindow`. A wider dial raises every rate, so no score catches it.
- Do not widen `tier1MaxDistanceRight` to reach a far-right amount. Reach it through `RowReach`.
- Set `RowReach` only on `t1.subtotal.right`, `t1.vat.right` and `t1.total.right`. Learned rules and `below` never read it.
- Keep `tier1DropRight` inside the window `TestTier1_TheDropBandStaysInsideItsMeasuredWindow` holds.
- Keep `pdfiumSplitGap` inside the window `TestPDFiumWords_SplitGapStaysInsideItsMeasuredWindow` holds.
- A widened shared lexicon pattern bumps `FingerprintVersion` and `BoxlessFingerprintVersion` together. The bump retires stored learned rules.
- A new owning-phrase entry with no rule needs neither bump. It resets only pages that print the phrase.
- Never hard-code a fingerprint prefix such as `v3:` or `b3:` in prose or a test needle. Read the constants.
- Add an owning-phrase entry to `t1OwningPhraseIDs` and give it a row in `alBareTokenCases`. An entry that resolves nothing must say so.
- Keep `t1PrintedPhraseIDs` on one line. A source scan reads it.
- Read the party vocabularies from `anchorLexicon` by id. Never copy a pattern into `party.go`.
- Keep `party.go` free of map types and reads of `Region`. `TestParty_UsesNoMapAndNoGeometry` scans it.
- Let a party heading ignore `anchorOutranked`. A token that spells `Supplier TIN` names the supplier louder.
- Scope only the party-less TIN rules to a party block. The last block owns the totals, so scope no amount rule.
- Keep the `From` arm of `supplier_name` anchored to the token start with a required terminator.
- Admit a verb inflection only through `alSuffix`, on `buyer_name` and `buyer_tin`. Noun-noun entries take no tail.
- Let a rightward read stop at an intervening label through `crossesALabel`. Build `labelTokens` once per page.
- Call no lexicon from the boundary predicate. `TestResolve_TheBoundaryPredicateScansNoLexicon` guards it.
- Read a letter-spaced label through `labelView`. Learning reads the token as printed.
- Change `doubtfulFields` together with `dtAmbiguous`. A field outside the list never presents as doubtful.
- Map `f.Value` and never `f.Reason` in `documentCreateInput` (`internal/importer`). A reason moves no stored value.
- Run `findTotal` only when `subtotal` and `vat` are decided and an anchored `total` exists.
- Skip `findTotal` when an anchored total already balances or a learned rule produced the total.
- Count only tokens with a `usableBox` as evidence. A DOCX token carries no box.
- Treat a learned rule as tenant data. A deploy cannot fix it and no screen retracts it.
- Report a misfiring learned rule to the corpus owner in the vault runbook index. Give its layout, tenant and field.
- Scope a learned rule to one tenant and one layout fingerprint. `AnchorRulesFor` reads by exact fingerprint.
- Round a learned `max_distance` up to two decimals. Cap it at the Tier-1 dial for its relation.
- A learned rule skips the outranking check that Tier-1 labels pass. A learned `Total` also fires inside `Sub-total`.
- Never grant `invoice_app` UPDATE or DELETE on `extraction_anchor_rules`. Displace a rule with a newer correction.
- An undone correction leaves its rule live. Only a second correction that derives a different rule displaces it.
- A typed correction on a geometric layout learns only when the derived rule re-reads page 1 as the typed value.
- A pointed correction is never self-checked. It can teach a misfire that a typed correction refuses.
- Bound the page-one read for a typed correction by `pageOneReadTimeout`. A failed read commits the correction and teaches nothing.
- Keep the accepted upload types in `acceptedDocumentTypes`, a package-level literal. It mirrors `ACCEPTED_PICKED_TYPES` in `frontend/app/src/lib/importFlow.ts`.
