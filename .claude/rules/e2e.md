# End-to-end tests

- Organise specs by capability, never by milestone or date. Name a file for its subject or for the axis it varies.
- Extend the capability flow in place to prove new value. Add no dated journey.
- Run specs against a deployed environment only. Start no local server.
- Keep the browser layer thin. Cover behaviour in Go tests and in the `e2e/api/` contract suite.
- Assert DOM and state. Fail a journey on any `console.error` or `pageerror`.
- Add no screenshot, pixel-diff or visual-snapshot gate.
- Carry a console-gate exception in `consoleGate.ts`, scoped by resource URL. Never change an API to satisfy the gate.
- Run Chromium only. Keep `workers: 1` in the api and topology configs. The smoke config runs fully parallel.
- Add each new topology spec file to a unit in `e2e/topology/shards.ts`. `shards.test.ts` fails on a spec in no unit.
- Run `library.spec.ts` in the `library` unit. It reads the public Library and uses no tenant.
- Run `blog.spec.ts` in the `blog` unit. It reads the public blog and uses no tenant.
- Run `blog-subscribe.spec.ts` in the `blog` unit. It submits the newsletter form to the fork gateway and uses no tenant.
- Keep a spec on `serial-lane` while it needs the seeded tenants 1111 and 2222. A shard gets its own tenant pair from `db/seed.e2e-shards.sql`.
- Sign in an app session with `signInAs(page, id, { tenantId })` from `e2e/personaSession.ts`. It admits the e2e member through `ensureMember`.
- Set an invitation token with `setInvitationToken`, or invite with `inviteWithToken`. A fork captures mail, so a spec cannot read a real token. `e2e/mail/` is the one exception: it reads real mail on the nightly.
- Set a deletion cancel-link token with `setDeletionLinkToken`.
- A staff account is an active `reviewer` of the seeded house company `ASComply (dev)`. `provisionStaffAccount` grants it through `/auth/mock/member`.
- Open a console with a staff session from `provisionStaffAccount` and `seedStaffSession`.
- Serve `/auth/mock/member`, `/auth/mock/invitation-token` and `/auth/mock/deletion-link-token` only from the `mockissuer` build.
- Never assume an empty table. Smoke, api and topology run in that order against one deployment, with no reset between them.
- Expect a Playwright retry to rerun a failed test against the rows its first attempt left.
- Create per-run-unique data, such as fresh TINs and random UUIDs. Act only on rows the spec created.
- Assert containment or a live-read comparison, never a literal count.
- Expect specs to leave rows in `auth.users`, `tenants`, `memberships` and `business_entities`. Every run registers a fresh address, so this is harmless.
- Expect the Support Console Submissions, Rules, Audit, Tenants, System health, AI usage and Blog screens to read real data. They are the console's only screens.
- Expect the app Rules screen to read the golden set and the custom rules from the server.
- Never publish a rule-set version in a topology spec. The api contract spec publishes only with the start date `3001-01-01`.
- Label a mock-backed assertion as a fixture check, in the spec. It pins a fixture, not a contract.
- Test the `library` SPA for render and consent only. It is static content with no backend.
- Test the `blog` SPA for render, layout and consent. It reads published posts from the gateway's public blog routes and its newsletter form posts to the gateway's public subscribe routes.
- Cover the blog's crawler HTML, sitemap and robots in `e2e/api/contract-blog-crawler.spec.ts`. Cover the `www` robots there too.
- Set `LIBRARY_URL` and `BLOG_URL` to each site's home, base path included.
- Take `new URL(...).origin` of `BLOG_URL` for an `Origin` header.
- Print the same site addresses from `ctl env` as `preview.sh urls` prints.
- Run `old-addresses.spec.ts` and `transport-security.spec.ts` against production after a load-balancer change.
- Keep `e2e/smoke/oldAddresses.ts` pure and unit-tested.
- Cover the library consent notice, the stored answer, the privacy link, the production-host-only tag and the chat gate in `e2e/smoke/library-consent.spec.ts`.
- Cover the blog consent and the blog chat gate in `e2e/smoke/blog-consent.spec.ts`.
- Cover the landing chat gate in `e2e/smoke/landing-chat.spec.ts`. Its live arm runs only against `https://www.ascomply.com`.
- Cover the app cookie notice, its layout, the PR-host chat gate and the sign-out cookie wipe in `e2e/topology/app-consent.spec.ts`.
- `passFrontDoor` seeds a denied consent record on the app origin when none is stored. Pass `consent: 'none'` to see the app notice.
- `ctl login` passes `consent: 'none'`. It writes no consent record.
- Stub every HubSpot chat host in `isStubbedHost`. A routed spec never reaches HubSpot.
- Never publish a policy in a topology spec. A topology spec may restore the tenant's own seeded policy through `ensureFirmPolicyActive`.
- Put the UI-driven approve and reject journey in `e2e/api/contract-invoice.spec.ts`, not in a topology spec.
- Treat the persona as an axis. Register personas, surfaces and coverage in `e2e/personas.ts`.
- Grade coverage as `drives` or `nav-only`. Add no `pending` grade.
- Downgrade a surface to `nav-only` only through `EXPECTED_NAV_ONLY` in `e2e/personas.test.ts`.
- Assert the sidebar marker `[title="Tenant verified via /v1/me"]` to prove a backend-resolved identity.
- Prove cross-tenant isolation with mock-issuer tokens for two tenants and `GET /api/tenancy/v1/me`. Both tenants exist in the seed, so RLS is the filter.
- Expect the fleet roll-up to report `sentry` `off` on a PR and `on` or `off` on the persistent environment. `auth` is exempt.
- Expect `notifications` to report `contacts` `fake` on a PR and `real` on the nightly, through `expectedContactsMode()`.
- Write the fork's URL variables, `WORKER_URL` and `GATEWAY_TOKEN`, the worker's `VALIDATION_URL` and `S2S_TOKEN`, and submission's `GATEWAY_URL` on each run. A fork never inherits them.
- Write `VITE_LIBRARY_URL` and `VITE_BLOG_URL` on `landing` on each fork.
- Write `VITE_LIBRARY_URL` and `VITE_BLOG_URL` on `app` on each fork.
- Write `VITE_APP_URL` and `VITE_LANDING_URL` on `library` on each fork.
- Write `VITE_GATEWAY_URL` and `VITE_LANDING_URL` on `blog` on each fork.
- Write `VITE_SUPPORT_URL` on `app` and `VITE_APP_URL` on `support-console` on each fork.
- Expect `library` to get no `VITE_GATEWAY_URL` on a fork. The blog URL is a CORS origin; the library URL is not.
- Expect a fork to accept registrations, send no mail and confirm at once. `fork-vars-before-urls` sets `GOTRUE_DISABLE_SIGNUP`, a blank SMTP host and `GOTRUE_MAILER_AUTOCONFIRM`.
- Expect a PR topology shard to stop at its first failed test, retry included. The `list` reporter prints later tests as "did not run"; the html and json reports mark them `skipped`. A retry-pass does not stop it.
